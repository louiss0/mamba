# Opt-in enum choice spellings

Enums may implement `MambaEnumValue`, an abstract interface with `String get value`, to use explicit choice spellings while commands continue reading typed enum members. Ordinary enums retain Enum.name spelling, but adopting enums use their values instead of implicitly accepting member names as aliases; all choice declarations and consumers must share this interpretation, including raw-string ChoiceVariadic validation. We chose this opt-in enum-owned contract over declaration-local mapping tables or mandatory migration of every existing enum, and include it in the first milestone alongside equals-attached short values; spellings are arbitrary exact case-sensitive strings, without trimming or normalization, including empty, whitespace-containing, and dash-leading values. Registration rejects duplicate spellings within each declaration's offered choices (including repeated entries of the same member), not across unoffered enum members; dash-leading named-option values still require inline supply under the token-ownership policy.
