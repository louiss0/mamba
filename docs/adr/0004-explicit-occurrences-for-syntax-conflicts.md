# Syntax conflicts concern explicit CLI occurrences

Mamba evaluates syntax conflicts using explicit CLI occurrences, independently of parsed defaults or other resolved values. We chose this over conflicts based on any non-default source or every resolved value so a fallback cannot make an otherwise valid CLI spelling unusable; `--replace` remains valid when `output` only defaults to `text`, while `--replace --output=text` conflicts. Conditions on effective values remain application logic, so occurrence information must survive independently of value resolution; tracking stays internal and ParsedInputs.contains keeps stored-value semantics. Conflict references may name any applicable ordinary named input, including global and propagated inputs, while reserved control paths remain outside ordinary conflict validation. Edges inherit when both referenced declaration identities remain applicable, including compatible overrides; losing a parent-local endpoint deactivates the edge, and an unrelated same-name child declaration cannot reactivate it.
